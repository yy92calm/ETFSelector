# 规则策略化与定期汇总落库优化方案

## 背景与问题

规则体系现状（rule_trainer / rule_engine / rules_routes）存在四个问题：

1. **全局混统**：`RuleTrainer.train()`（rule_trainer.py:43）从 AutoStrategyLog 统计 regime→配置 规律时不过滤 strategy_id，所有策略日志混在一起。策略A（科技池）的行为被当成策略B（债券池）的"规律"
2. **回测配置越池**：`compute_daily_allocation` 的 AI 规则分支（rule_engine.py:130-143）输出只按"当日有指标的ETF"过滤，不收敛到策略自己的标的池——债券策略的规则驱动回测可能产出科技ETF配置。`strategy.allocation_config` 仅在无指标时兜底，形同虚设
3. **规则不落库、无定期汇总**：`train()` 每次现场统计，无持久化快照，无法追溯"当时用的是哪版规则"；唯一周期性触发是周复盘进化步骤的即时调用
4. **缓存永不失效**：rule_engine 的 `invalidate_cache()`（rule_engine.py:99，注释"新分析完成后调用"）全库无调用方，进程内存中的规则加载后不随新分析数据更新

## 设计原则

```
regime 判定（市场状态）      → 全局共享：来自全市场 ETFDailyIndicator，是客观事实
regime → 配置 映射（规律）   → 按策略统计：不同标的池，同一 regime 的最优配置不同
输出收敛                    → 任何分支产出的配置必须收敛到该策略标的池内
```

兜底链（逐级回退）：

```
本策略AI规则（数据量达标）
→ 全局AI规则（数据量达标）
→ 确定性规则（REGIMEAllocation，仅分配策略池内的类别ETF）
→ 策略静态配置（allocation_config）
```

## 模块改动

### 1. RuleTrainer 策略化（rule_trainer.py）

- `train(db, days=90, strategy_id=None)`：strategy_id 非 None 时 `_load` 过滤 `AutoStrategyLog.strategy_id == strategy_id`
- 返回结果增加 `"scope": "strategy:{id}" | "global"` 字段
- 回放规则（replay）保持全局不变（回放即历史补数据，无策略归属价值时仍可兜底）
- rules_routes API 不传 strategy_id，保持全局行为，前端无感

### 2. 新表 RuleSnapshot（app/models/strategy.py 追加 + init_db 注册）

- `strategy_id`（nullable，None=全局快照，index）
- `snapshot`（JSON，train() 完整结果）
- `source`（weekly_review / manual）
- `days_covered`（覆盖天数）、`created_at`
- 写入时机：周复盘每个策略复盘前，落两份——本策略快照 + 每日管道结束时落全局快照（低频，不额外加定时任务）

### 3. compute_daily_allocation 策略化 + 越池修复（rule_engine.py）

- 签名追加 `strategy_id=None`：`compute_daily_allocation(trade_date, db, base_allocation, strategy_id=None)`
- 取规则顺序：本策略快照/现算（`train(strategy_id=...)`）→ 全局 → 确定性规则（现状）
- **新增统一出口过滤**：产出 allocation 后按 `base_allocation.keys()`（策略标的池）过滤再归一化；过滤后为空则回退下一级
- 确定性规则分支同步过滤：`_distribute_by_score` 输入 indicators 先按策略池过滤
- `get_regime_info` 同步加 strategy_id（回测逐日 analysis 用），规则来源标注细化：`ai_history_strategy / ai_history_global / deterministic`

### 4. 回测传参（backtest_service.py）

- `engine.run` 中 rule_based 分支调用处传 `strategy_id=strategy.id`（compute_daily_allocation 与 get_regime_info 两处）

### 5. 规则读取接入落库快照（rule_engine.py）

- `_ensure_trained_rules(db)` 改为按 scope 的分层缓存 `_trained_by_scope: dict`（key: `"global"` / `"strategy:{id}"`）
- 加载顺序：内存缓存 → RuleSnapshot 最新落库快照（7天内视为新鲜）→ 现场计算（并顺手落一份快照，source=manual）
- 数据量门槛沿用现有 `days >= 10`

### 6. 缓存失效修复

- 每日管道 `_job_daily_pipeline` 末尾（autonomous 阶段完成后）调用 `get_rule_engine().invalidate_cache()`：新分析日志产生后次日规则即刷新
- 周复盘快照落库后同样失效

### 7. 进化提示词用本策略规则（review_service.py）

- `trigger_review` 流程调整为：生成经验 → **落本策略规则快照 + 全局快照** → `_evolve_prompt` 改为 `train(db, days=90, strategy_id=strategy_id)`（失败回退全局），使进化提示词「有效规律」节只含本策略自己的规律

## 实施步骤与验证

| 步骤 | 验证 |
|------|------|
| 1. train(strategy_id) 参数化 | 单测：两条策略日志，按策略统计只含各自记录 |
| 2. RuleSnapshot 表 + 注册 | 建表冒烟 |
| 3. compute_daily_allocation 策略化+池过滤 | 单测：构造策略池 {债券ETF}，AI规则含科技ETF，输出不含池外标的且归一化；兜底链逐级回退 |
| 4. 回测传参 | 既有回测测试回归；规则回测 daily_data.allocation ⊆ 策略池 |
| 5. 分层缓存+快照读取 | 单测：有新鲜快照时不现算（mock 计数）；超7天现算并落库 |
| 6. 缓存失效挂载 | 代码审查 + 管道冒烟 |
| 7. 进化原料策略化 | 既有进化测试改造后回归 |
| 8. 全量 pytest 回归 | 除已知历史失败 test_full_debate_flow 外全绿 |

## 不做的事

- 不改 rules_routes 对外 API 契约（默认全局），前端规则页无感
- 不引入新定时任务（全局快照搭每日管道车，策略快照搭周复盘车）
- 不动确定性规则表 REGIMEAllocation 本身（类别→比例的先验仍然全局）
