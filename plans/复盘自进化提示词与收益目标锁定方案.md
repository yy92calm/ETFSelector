# 复盘自进化提示词与收益目标锁定方案

## 需求

1. LLM 通过复盘修改提示词实现自进化；RuleTrainer 提取的规则也作为提示词之一沉淀
2. 每个策略的收益目标不可变（仅锁 AI，用户前端仍可调），AI 必须努力完成目标

## 现状对照

| 组件 | 现状 | 缺口 |
|------|------|------|
| 提示词 | `SYSTEM_PROMPT` 代码写死（loop.py:68）+ 技能摘要 + 每轮「系统状态快照」（context.py，user-role 注入，不落库） | 无可进化层 |
| 复盘 | `ReviewService.trigger_review`（review_service.py:137）：周度/异常复盘生成 Experience 经验库 | 经验只是 AI 可选工具查询（get_experience_insights），不主动进提示词 |
| 规则提取 | `RuleTrainer.train`（rule_trainer.py:43）从 AutoStrategyLog 统计 regime 规则 | 只喂回测 rule_engine，不进 LLM 提示词 |
| 收益目标 | `Strategy.target_monthly_min/max`（月5%~10%）；`get_monthly_progress`（portfolio_service.py:278）已算当月进度 | 未注入 AI 快照；SYSTEM_PROMPT 无目标条款 |
| 工具面 | `create_strategy`/`update_allocation` 均不暴露 target 参数 | AI 无法改目标（已天然满足），仅需提示词层面约束 |

## 关键约束

- 静态 system prompt 跨轮字节稳定（provider prompt cache），进化提示词只能注入快照（user-role）
- 进化是复盘的一部分：跟随现有周度/异常复盘触发，不加每日负担
- LLM 解析失败不得破坏复盘主流程（沿用 _generate_experiences_with_llm 的容错模式）
- 新表走 init_db() 建表，不引入 Alembic

## 模块结构

### 1. 新模型 StrategyEvolvedPrompt（app/models/strategy.py 追加）

- `strategy_id`（unique index）、`prompt_text`（当前进化提示词全文）、`version`（每次进化+1）、`source_type`（weekly/anomaly）、`updated_at/created_at`
- 单策略单行（upsert），审计靠 AutoStrategyLog `action_type="prompt_evolved"` 记录进化说明
- 注册：app/models/__init__.py 导出 + app/db/database.py init_db 导入

### 2. 进化步骤（review_service.py，trigger_review 末尾追加）

`_evolve_prompt(strategy_id, review_type, experiences, db)`：

- 原料：本期经验列表 + `RuleTrainer.train(db, days=90)` 的 regime_rules 摘要 + `get_monthly_progress` 进度 + 当前进化提示词
- LLM 输出 JSON `{"prompt_text", "evolution_summary"}`，meta prompt 约束：
  - 目标是不可变使命，禁止任何调整目标本身的条目
  - 结构化分节：[目标使命]/[有效规律]/[教训禁区]/[执行纪律]
  - 总长≤800字，保留仍有效旧条目、淘汰过时条目
- upsert（version+1），写 AutoStrategyLog；LLM 失败则跳过并 warning

### 3. 上下文注入（context.py）

- `_get_strategies_summary`：每策略追加 `目标进度:{get_monthly_progress().text}`
- 新 section「策略进化提示词」：active 且有进化提示词的策略注入 prompt_text（有则注入，无则跳过）

### 4. 目标锁定（loop.py SYSTEM_PROMPT 追加静态条款）

- 收益目标是不可变使命：禁止通过任何工具或方式调整 target_monthly_min/max，只能优化打法
- 进度落后（behind）时的行为准则：提高规则执行纪律、严格执行止损、主动复盘，但不得放大风险敞口硬冲目标（风控熔断优先级更高）

## 实施步骤与验证

1. 模型 + init_db 注册 → 验证：pytest 建表冒烟
2. 进化步骤 → 验证：单测 mock LLM，upsert 后 version=1，再次复盘 version=2；LLM 失败时复盘不受影响
3. 上下文注入 → 验证：单测 snapshot 含「目标进度」与进化提示词文本
4. SYSTEM_PROMPT 条款 → 验证：py_compile + 无回归 pytest
5. 全量 `pytest` 回归
