# 个股数据仅限板块辅助改造方案

## 背景与原则

系统持仓唯一标的为 ETF。个股层面数据（baostock 基本面、东财热门股排行）只允许用于辅助判断板块（行业）状态，不允许以任何形式呈现为个股投资建议，更不允许进入交易链路。

## 现状对照

| 环节 | 现状 | 与原则的差距 | 结论 |
|---|---|---|---|
| 标的池与持仓 | etf_basic 270 只全为场内 ETF；holding/trade_record 无非 ETF 代码；generator/market_analyst prompt 强制 ETF 白名单；`_validate_etf_codes` 三重闸口 | 无 | 合规，不动 |
| 个股基本面 → 行业性价比 | `value_model_service.compute_industry_scores` 用池内个股估值/增速聚合出 IndustryScore，每日调度 | 评分仅到研究页展示，未进入任何决策 Agent | 链路未闭环，需接入 |
| 个股精选列表 | `/api/research/stock-picks` 返回跨行业混排的个股 TOP30，前端"个股安全边际榜"直接展示荐股式列表 | 呈现为个股推荐，超出"辅助板块"范畴 | 需改造 |
| 热门股舆情 | `sentiment_service` 将东财热门股代码拼接进舆情条目，喂给 LLM 情感分析与 SentimentAnalystAgent | prompt 未声明个股仅作板块热度参考 | 需加约束 |

## 关键约束

- 不改变交易链路：`_validate_etf_codes` 闸口、ETF 白名单 prompt、`compute_adjustment` 均不动
- 不新增依赖、不新增表；IndustryScore 已有每日落库（scheduler stage: fundamental）
- Agent 的 `analyze()` 失败时返回 `{"error": ...}` 而非抛异常；IndustryScore 无数据时必须优雅降级（跳过该段注入）
- 前端保持原生 ES6+，无构建工具；A股红涨绿跌配色约定不变
- 个股精选数据接口保留（研究用途），仅改展示结构为"以板块为主维度"

## 模块结构与接入点

```
app/agents/macro_cycle_agent.py     # 修改：PROMPT 增加行业性价比排名段；analyze() 查询 IndustryScore 注入 market_data
app/services/sentiment_service.py   # 修改：SENTIMENT_ANALYSIS_PROMPT 增加个股用途约束
app/agents/sentiment_analyst.py     # 修改：PROMPT 舆情数据说明段增加同一约束
static/workbench.html               # 修改：面板"个股安全边际榜"改名并按行业分组展示
static/js/workbench.js              # 修改：research 视图渲染逻辑，按 industry 分组
tests/                              # 新增：IndustryScore 注入与分组的单测
```

## 设计

### 一、行业性价比接入宏观周期 Agent

`MacroCycleAgent.analyze` 现有输入为价格代理（market_data）。新增一段：

```
## 行业盈利-估值性价比排名（基于池内个股基本面聚合，反映板块层面信号）
{industry_ranking}
```

- 查询 `get_value_model_service().get_industry_ranking(db, days=1)`，取前 5 与后 5，格式化为 `{行业, score, rank}` 列表
- 表为空或查询异常时传 `"暂无行业评分数据"`，prompt 其余部分不变
- 明确在 prompt 中声明：该数据来自个股聚合，仅用于板块超配/低配判断

效果：个股数据 → 行业评分 → sector_rotation 建议 → 多空辩论/主管裁决 → ETF 配置，实现"辅助板块"的完整闭环，且不产生任何个股标的输出。

### 二、个股精选改造为板块样本验证

前端 research 视图（`workbench.js` 约 479-540 行）：

- 面板标题改为"板块内样本验证"，副标题注明"按行业分组展示，仅供验证板块成色，不构成个股推荐"
- 渲染逻辑改为：将 `/api/research/stock-picks?top_n=30` 返回结果按 `industry` 分组，行业按组内最高 score 排序；每个行业展示组内前 3 只样本股（代码、名称、PE、PEG、自身 PE 分位、score）
- 后端 API 与 `get_stock_picks` 逻辑不动（数据仍是个股维度，展示维度改为行业优先）

### 三、舆情链路个股用途约束

两处 prompt 各增加一条规则（不改变其余内容）：

- `sentiment_service.SENTIMENT_ANALYSIS_PROMPT`：在输出要求后追加"热门股排行榜中的个股代码仅用于感知市场热度与板块归属，不得将其本身作为投资标的判断依据"
- `agents/sentiment_analyst.SentimentAnalystAgent.PROMPT`：在舆情数据说明段追加"个股热点信息仅反映板块情绪强度，结论须落在板块/ETF 层面"

## 实施步骤

1. MacroCycleAgent 注入 IndustryScore 排名 → 验证：`IndustryScore` 表有数据时 prompt 含排名段；清空后 `analyze()` 正常降级不报错
2. 舆情两处 prompt 约束 → 验证：`grep` 确认约束文案存在；采集流程跑通一次
3. workbench research 视图按行业分组渲染 → 验证：浏览器打开研究视图，个股按行业成组展示，无跨行业混排榜单
4. 新增单测：分组函数 + macro agent 注入/降级两例 → 验证：`pytest tests/ -k "industry or macro"` 通过
5. 全量回归：`pytest` 通过，每日管道（净值→再平衡→舆情→AI分析）手动触发一次确认无异常

## 不做的事

- 不下线 stock-picks 接口（保留研究价值，展示已改造）
- 不将 IndustryScore 接入 rule_engine 硬规则（先在 Agent 层验证信号有效性，再议规则化）
- 不动 `ef.stock.get_quote_history`（efinance 接口形式，实际取的就是 ETF 行情）
