# 任务视图管道过程可视化优化方案

## 问题

1. **看不到过程**：任务视图只有结果（执行历史的成功/失败+耗时），每日管道 8 个阶段进行到哪一步、每步做了什么完全不可见；检查点 API（/api/tasks/checkpoint）已有但前端未使用
2. **命名含糊**：任务列表/统计里的"阶段·自主决策"（daily_pipeline.autonomous）看不出是干什么的；任务行描述"完整管道：净值更新 → …"过长换行，观感拥挤（"挤在两行"）
3. **结果摘要不可读**：执行历史的 result_summary 直接 JSON.stringify 展示

## 改动

### 1. 后端新接口 `GET /api/tasks/pipeline/today`（task_routes.py）

返回今日 daily_pipeline 的过程数据，一次请求组装：

- `checkpoint`: status（not_started/running/completed/failed）/ error_message / updated_at
- `stages`: 按管道顺序的 8 个阶段数组，每项含：
  - `stage` / `name` / `description`（清晰的一句话说明）
  - `status`: not_started / running / done / failed
    （判定：今日该阶段最新一条 TaskExecutionLog 为 running→运行中、failed→失败；stage 在检查点 done_stages→完成；否则未开始）
  - `started_at` / `duration_seconds` / `result_summary` / `error_message`

### 2. 前端「今日管道过程」面板（任务视图顶部，workbench.js/html/css）

- 8 阶段横向步骤条：节点圆点状态色（未开始灰/运行中蓝+呼吸动画/完成绿/失败红）+ 阶段名 + 耗时
- 管道运行中每 5s 自动轮询，完成后停止
- 点击阶段展开详情：一句话说明、开始时间、耗时、结果摘要（可读化）、错误信息
- 汇总行：整体状态 + 已完成 x/8 + 管道最近错误

### 3. 结果摘要可读化（formatTaskSummary）

result_summary 常见字段翻译为中文短句：success_count→"成功x"、fail_count→"失败y"、total、count、message；未知结构回退键值列出。

### 4. 文案与布局

- TASK_DEFINITIONS 管道描述精简为一行不换行；阶段命名统一带"AI"前缀说明（autonomous→"AI自主决策"，说明"LLM 综合分析并自主调仓/建仓/暂停策略"）
- task-row 布局：名称行加定时 badge；描述单行省略（text-overflow）；meta 单行 flex；行 hover 展开完整描述（title 属性）
- 执行历史/统计卡命名映射同步更新（阶段·自主决策→AI自主决策）

## 验证

- 后端：pytest 新增接口单测（今日无记录/部分完成/有失败 三态）
- 前端：node --check；手动验证步骤条三态渲染与轮询停止条件
- 全量 pytest 回归
