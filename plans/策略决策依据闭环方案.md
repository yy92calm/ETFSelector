# 策略决策依据闭环方案

## 问题

上一轮打通了「视图→策略」的归属关系，但**策略侧看不到依据**，且依据接入不齐：

| 依据来源 | 决策链现状 | 可见性 |
|---|---|---|
| 行情（5维扫描/评分/技术面） | ✅ 已进轮动辩论（5分门槛） | 策略持仓表有得分/动量列，但无「换仓触发差距」等结论 |
| 研究（行业性价比） | ✅ 已注入轮动辩论 `industry_value` | ❌ 策略页不可见 |
| 规则（regime→配置映射） | ❌ 实盘决策从不读取，仅规则回测用 | 规则页可看，但与策略决策无关联 |
| 舆情 | ✅ 进分析（情绪字段） | 仅分析卡一角 |

用户目标：**行情/研究/规则都要为策略提供依据** —— 即依据要①进决策、②看得见、③可追溯。

## 设计

### 1. 规则进决策（与 industry_value 同等待遇）

- `RuleEngine.get_rule_suggestion(trade_date, db, strategy_id, base_allocation)`：当前市场状态下的规则建议配置（AI历史规则 → 确定性规则 → 静态配置兜底），收敛到策略标的池并归一化，附与当前配置的偏离、规则来源、样本说明
  - 内部抽出 `_resolve_allocation()` 统一返回 (配置, 来源分支)，`compute_daily_allocation` 委托之（行为不变，供回测复用）
- `rotation_service.evaluate_rotation`：构建 rule_signal → 注入辩论材料（三个 prompt 新增「规则参考」段）→ plan 返回 `rule_signal`
- 新只读工具 `get_rule_suggestion(strategy_id)`：供 AgentLoop 自主决策与对话调用
- `tasks/prompts/autonomous_instruction.md`：第1步明确要求查阅四类依据（行情/研究/规则/舆情），结论中说明引用了哪些

### 2. 依据聚合（新服务）

`StrategyEvidenceService.get_evidence(strategy_id, db)` → 五段：

| 段 | 内容 |
|---|---|
| market | 持仓/池内评分排名动量趋势波动 + 最强候选 + 与最弱持仓的差距 vs 5分门槛 + 禁入名单 |
| research | 池内标的 → 行业性价比（rank/score/total/as_of） |
| rules | regime + 规则来源 + 建议配置 + 与当前配置偏离 + 样本说明 |
| sentiment | 近7日涉本策略标的的舆情条数与均分 + 最近条目标题 |
| decision | 最近一次 analyzed 决策记录（日期/动作/理由/关键信号）+ 该次引用的依据（evidence.sources_cited） |

接口：`GET /api/workbench/strategy-evidence?strategy_id=`

### 3. 决策留痕

`_record_autonomous_analysis` 在写 analyzed 记录时附 `analysis_result["evidence"]`：

- `sources_cited`：从自主决策工具调用映射（get_market_position_signal/get_technical_indicators→行情，get_industry_ranking→研究，get_rule_suggestion→规则，get_sentiment_data→舆情）
- `snapshot`：决策时点四类依据快照（复用 evidence service，可复盘）

## 前端

策略视图每个策略块内新增「决策依据」区（默认可见）：

- 顶部一行结论条：最近决策（日期/动作）+ 引用依据标签（行情/研究/规则/舆情）
- 2×2 卡片：行情依据 / 研究依据 / 规则依据 / 舆情依据，含差异与结论（如「最强候选领先最弱持仓 12.4 分 ≥ 门槛 5 分」）
- 互链：行情行→行情视图、行业→研究视图、规则→规则视图、舆情→舆情视图
