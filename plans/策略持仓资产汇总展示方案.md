# 策略当前持仓补充总资产/资产净值/现金方案

## 现状对照

| 项 | 现状 |
|---|---|
| 数据模型 | `PortfolioSnapshot` 已有 `total_asset`（总资产）/`cash`（现金）/`market_value`（持仓市值）/`profit_pct`，每策略每交易日一条（app/models/portfolio.py:8） |
| 持仓 API | `/api/portfolio/{id}/holdings` 只返回持仓明细列表（代码/数量/成本/现价/市值），无资产汇总（app/routes/portfolio_routes.py:54） |
| 策略卡片当前持仓区 | 只在表格底部显示「持仓市值 ¥X」，无总资产/净值/现金（workbench.js:1496） |
| 占比口径 | 前端占比 = 个股市值 / Σ持仓市值（workbench.js:1499），而配置比例 allocation_config 的口径是占总资产（compute_adjustment 以 total_asset 为分母），两处分母不一致 |
| 概览展开详情 | 底部只有「最新资产 ¥X」和近20日涨跌（workbench.js:555），无现金/净值 |

## 口径定义

- **总资产** = 最新快照 `total_asset`（= 持仓市值 + 现金）
- **现金** = 最新快照 `cash`
- **持仓市值** = 最新快照 `market_value`（顺带补齐展示）
- **资产净值** = 单位净值口径：`total_asset / initial_capital`，保留 4 位（期初 = 1.0000），符合基金净值习惯
  - 说明：若按「总资产 − 负债」口径，本系统无负债，数值与总资产相同、展示冗余；故采用单位净值口径。如需改为绝对额口径，评审时指出即可
- **无快照（尚未建仓）**：总资产 = 现金 = `initial_capital`，持仓市值 = 0，净值 = 1.0000

## 关键约束

- 只读改动：不碰 portfolio_service 的快照生成逻辑，只加读取接口
- 前端纯静态 JS，无构建工具，保持现有代码风格
- 占比口径统一为「占总资产」，与 allocation_config、compute_adjustment 一致
- API 向后兼容：`holdings` 列表字段不动，新增 `summary` 对象

## 实施步骤

1. **后端**：`get_holdings` 路由查最新 `PortfolioSnapshot`（strategy_id 过滤，trade_date 倒序第一条），组装 `summary = {market_value, cash, total_asset, nav, as_of}`；无快照按口径给初始值 → 验证：有快照/无快照两分支断言
2. **前端策略卡片**：`loadStrategyHoldings` 表格上方渲染汇总条「总资产 / 资产净值 / 现金 / 持仓市值（含日期）」；占比分母改为 summary.total_asset → 验证：前端展示 + 未建仓策略显示初始口径
3. **前端概览详情**：`renderStrategyDetail` 的 footer 补「现金 ¥X · 净值 X.XXXX」，占比分母同样改总资产 → 验证：展开详情展示齐全
4. `pytest` 全量回归
