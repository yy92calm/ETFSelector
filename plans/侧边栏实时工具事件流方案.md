# 侧边栏实时工具调用事件流方案

借鉴 OpenWorker-Core-Reference（coworker 包）的事件流模型：agent 循环逐步发出类型化事件
（`TOOL_STARTED → TOOL_FINISHED → ASSISTANT_MESSAGE → TURN_END`），UI 消费事件流实时渲染，
而不是等全部跑完再一次性出结果。

## 现状对照

| 能力 | 现状 | 差距 |
|---|---|---|
| 侧边栏反馈 | `POST /api/chat` 同步返回，期间只显示三个点 typing 动画 | agent 的工具调用过程完全不可见 |
| 工具展示 | 全部跑完后一次性输出一行 `⚙ 工具名` 汇总 | 无执行中/完成/失败状态，无过程感 |
| 会话延续 | 完成后 `session_id` 回填，前端可继续 | 事件流方案需保持相同行为 |

## 关键约束

- 路由沿用 `APIResponse` 外的独立 SSE 端点，保留旧 `POST /api/chat` 作为回退，不破坏兼容
- AgentLoop 多轮 ReAct 逻辑不复制粘贴：抽公共事件生成器，`run()` 与 `run_streaming()` 共用
- 前端沿用原生 ES6 + fetch ReadableStream 解析 SSE，不引入框架
- 流式失败（网络/404/非 event-stream）自动回退到旧的非流式接口

## 后端改动

### app/agent_core/loop.py

抽公共生成器 `_iter_events(user_message, session_id, db)`，yield 统一事件字典：

```
turn_start        {"session_id": ...}
tool_started      {"seq": 1, "tool": "get_market_overview", "arguments": {...}}
tool_finished     {"seq": 1, "tool": "...", "status": "success"|"error", "preview": "..."}
assistant_message {"content": "..."}
turn_end          {"session_id": ..., "tool_calls": [...]}
error             {"error": "..."}
```

- `run()` 改为消费 `_iter_events`，重建 `AgentResponse`（行为保持与现有一致）
- 新增 `run_streaming()`，逐条转发事件给调用方
- `run_autonomous()` 不动

### app/routes/chat_routes.py

新增 `POST /api/chat/stream`：

- 同步生成器 + `StreamingResponse(media_type="text/event-stream")`，Starlette 在线程池迭代，不阻塞事件循环
- 每条事件 `data: {json}\n\n`，`ensure_ascii=False`
- `get_db` yield 依赖在响应发送完成后才销毁，流式期间 db 会话可用

## 前端改动

### static/js/chat.js

- `send()` 优先走流式：`fetch /api/chat/stream` + `ReadableStream` 逐帧解析 SSE
- 事件分发：
  - `tool_started` → 追加实时工具气泡（⚙ 名称 + 旋转动画），移除 typing
  - `tool_finished` → 更新气泡为完成 ✓ / 失败 ✗
  - `assistant_message` → 渲染最终回复
  - `turn_end` → 回填 session_id、结束 loading、刷新工作台、重载会话列表
  - `error` → 渲染错误
- 新增 `this.streaming` 守卫防重入；流式失败自动回退旧 `POST /api/chat`

### static/css/workbench.css

- `.tool-info` 增加 `.running`（spinner）/ `.done` / `.error` 状态样式
