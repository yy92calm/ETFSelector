# 分析与规则视图策略关联优化方案

## 问题

分析与规则两个视图的数据接口全部写死策略1：
- `loadAnalysesView` → `/api/workbench/daily-analysis?days=60`（后端默认 strategy_id=1）
- `loadAnalysesView`/`loadRulesView` → `/api/workbench/rules?days=60`（后端默认 strategy_id=1）
- `_runRuleBasedBacktest` → POST body `strategy_id: 1`
- `loadMonthlyTarget` → `/api/workbench/monthly-target?strategy_id=1`

界面无策略选择器、无归属标识，多策略时分析与规则完全不知道是"谁的"。上一轮给规则学习面板加的范围选择器只覆盖该面板，与其余数据割裂。

## 设计

**视图级共享策略选择器**：分析与规则视图头部各放一个同步的策略选择器，选中值存 `Workbench._analysisStrategyId`，驱动视图内全部数据源。

- 选项：`全局（仅规则）` + 所有自动策略（running 优先），默认第一个 running 自动策略
- 切换即同步两个选择器并重载当前视图

**数据接线**：

| 数据源 | 改法 |
|--------|------|
| 每日AI分析列表 | `daily-analysis?strategy_id=X`；选"全局"时列表提示需选具体策略 |
| 提取的轮动规则 + 配置时间线 | `workbench/rules?strategy_id=X` |
| 规则学习面板 | 删除面板内部选择器，共用视图选择器；`/api/rules?strategy_id=X` |
| 重新提取按钮 | `/api/rules/train?strategy_id=X` |
| 规则驱动回测 | POST body `strategy_id: _analysisStrategyId` |
| 月度目标进度条（策略视图） | `_getDefaultStrategyId()`：第一个 running 自动策略，兜底1 |

后端接口均已支持 strategy_id 参数，无需改动；写死的默认值保留作向后兼容，前端全部显式传参。

## 验证

- node --check；切换选择器确认分析列表/轮动规则/规则学习/回测请求带对 strategy_id（DevTools 网络）
- 全量 pytest 回归（后端无改动）
